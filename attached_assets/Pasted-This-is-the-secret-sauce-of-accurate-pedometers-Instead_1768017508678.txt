This is the "secret sauce" of accurate pedometers. Instead of saying "a step is anything over 1.2g," a dynamic threshold adapts to whether the user is power-walking, strolling, or just fidgeting.Here is a logic framework for a Dynamic Threshold Step Detection algorithm.The Core Logic: "The Peak & Valley" ApproachThe goal is to find the midpoint between the highest acceleration (peak) and lowest acceleration (valley) within a small window of time.1. Pre-ProcessingBefore checking for steps, you must calculate the Vector Magnitude so the phone's orientation doesn't matter.$$Mag = \sqrt{a_x^2 + a_y^2 + a_z^2}$$Then, pass this through a Simple Moving Average (SMA) filter to smooth out the "jitter."2. Pseudocode: Dynamic ThresholdingThis logic should run inside your sensor listener (e.g., onSensorChanged).Plaintext// INITIALIZE VARIABLES
List magnitudeWindow = [] // Store last 50 readings (~1 second of data)
float dynamicThreshold = 0
float precision = 0.2 // Sensitivity floor to ignore micro-vibrations
long lastStepTime = 0
int stepBufferCount = 0
boolean isStepBufferActive = true

FUNCTION onSensorUpdate(currentAcceleration):
    // 1. Calculate Magnitude and smooth it
    float mag = calculateMagnitude(currentAcceleration)
    magnitudeWindow.add(mag)

    // 2. Keep the window at a fixed size (e.g., 50 samples)
    if magnitudeWindow.size > 50:
        magnitudeWindow.removeFirst()

    // 3. Update Dynamic Threshold every 50 samples
    float max = getMaxValue(magnitudeWindow)
    float min = getMinValue(magnitudeWindow)
    dynamicThreshold = (max + min) / 2

    // 4. STEP DETECTION LOGIC
    // Check if the signal is crossing the threshold upward
    if (mag > dynamicThreshold + precision) AND (mag > previousMag):
        long currentTime = getCurrentTimeMillis()
        
        // Time Window: Human steps are usually 200ms to 2000ms apart
        if (currentTime - lastStepTime > 200) AND (currentTime - lastStepTime < 2000):
            
            // 5. THE "6-STEP" VALIDATION BUFFER
            if isStepBufferActive:
                stepBufferCount++
                if stepBufferCount >= 6:
                    totalSteps += stepBufferCount // Add the 6 steps we held back
                    isStepBufferActive = false
            else:
                totalSteps++ // Normal counting
            
            lastStepTime = currentTime
        
    // Reset buffer if no movement detected for 3 seconds
    if (currentTime - lastStepTime > 3000):
        isStepBufferActive = true
        stepBufferCount = 0

    previousMag = mag
Why this works better than a "Fixed" threshold:The Midpoint Logic: By calculating $(max + min) / 2$, the threshold moves with the user. If they start running, the peaks get higher, and the threshold automatically moves up to match, preventing "double-counting" from small bounces.The Precision Floor: The precision variable (0.2 in the example) ensures that if the phone is just sitting on a table vibrating slightly, the $max$ and $min$ will be too close together to trigger a "step."The Time Window: This is your best defense against "The Shakers." If someone shakes the phone 10 times in one second, the algorithm will reject them because the currentTime - lastStepTime will be less than 200ms.Critical Edge Cases to HandleThe "Bus" Problem: High-frequency vibrations from a vehicle can look like steps. A Low-Pass Filter is mandatory to strip out any signal above 5Hz.The "Pocket" Shift: When a user adjusts their phone in their pocket, it creates a massive spike. Your algorithm should ignore any $max$ that is physically impossible for a human (e.g., $> 4.0g$).
